## Overview

The QR Code feature is a comprehensive solution for generating, scanning, exporting, and managing QR codes within the SSS Flutter application. The system implements a proprietary QR code format with deep linking capabilities, allowing QR codes generated by this system to directly open the app and display associated data.

### Key Features
- **QR Code Generation**: Create customizable QR codes with embedded identifiers, color themes, and branding
- **QR Code Scanning**: Real-time camera-based QR code scanning with system verification
- **Deep Linking**: Native deep link support (`sss://qr/<id>`) for seamless app integration
- **Export Capabilities**: Export QR codes as PNG images or PDF documents
- **Sharing**: Share QR codes via system share sheet (email, messaging, etc.)
- **System Verification**: Verify if scanned QR codes were created by this system
- **Custom Branding**: Support for embedded letters/emojis, custom colors, and branded cards

## Technologies and Libraries

### Core Dependencies

#### 1. **qr_flutter** (v4.1.0)
- **Purpose**: QR code generation and rendering
- **Usage**: 
  - Generates QR code widgets with customizable colors, sizes, and error correction levels
  - Supports embedded images (though currently using text overlay for identifiers)
  - Error correction level: Medium (M) - balances data capacity and error recovery
- **Key Features Used**:
  - `QrImageView` widget for rendering QR codes
  - Customizable foreground/background colors
  - Error correction levels (L, M, Q, H)

#### 2. **mobile_scanner** (v5.2.3)
- **Purpose**: QR code and barcode scanning using device camera
- **Usage**:
  - Real-time camera scanning in `QRScannerScreen`
  - Detects and decodes QR codes and barcodes
  - Provides barcode capture callbacks
- **Key Features Used**:
  - `MobileScanner` widget for camera view
  - `MobileScannerController` for controlling scanner state
  - `BarcodeCapture` for handling scan results

#### 3. **uni_links** (v0.5.1)
- **Purpose**: Deep linking support for app navigation
- **Usage**:
  - Handles incoming deep links (`sss://qr/<id>`)
  - Listens for deep links while app is running
  - Processes initial deep link when app is opened via link
- **Key Features Used**:
  - `getInitialLink()` for app launch deep links
  - `linkStream` for listening to deep links during runtime

#### 4. **share_plus** (v7.2.1)
- **Purpose**: System share sheet integration
- **Usage**:
  - Shares exported PNG/PDF files via system share sheet
  - Supports email, messaging apps, cloud storage, etc.
- **Key Features Used**:
  - `Share.shareXFiles()` for sharing files with subject and text

#### 5. **pdf** (v3.10.7)
- **Purpose**: PDF document generation
- **Usage**:
  - Creates PDF documents containing QR codes
  - Includes metadata (title, description, timestamp, system ID)
  - Formats QR code images in A4 layout
- **Key Features Used**:
  - `pw.Document()` for PDF creation
  - `pw.Page()` with A4 format
  - `pw.MemoryImage()` for embedding QR code images

#### 6. **path_provider** (v2.1.1)
- **Purpose**: Platform-specific file system paths
- **Usage**:
  - Gets downloads directory (Android) or documents directory (iOS)
  - Provides file paths for saving exported QR codes
- **Key Features Used**:
  - `getExternalStorageDirectory()` for Android
  - `getApplicationDocumentsDirectory()` for iOS

#### 7. **permission_handler** (v11.1.0)
- **Purpose**: Runtime permission management
- **Usage**:
  - Requests storage permissions on Android 13+ for file exports
  - Handles permission grants/denials gracefully
- **Key Features Used**:
  - `Permission.storage.request()` for Android storage access

#### 8. **image** (v4.1.3)
- **Purpose**: Image manipulation utilities
- **Usage**: Available for future image processing needs


#### Deep Link Generation
- Automatically generated for all QR codes created in the system

## Data Model

### QRData Structure

```dart
class QRData {
  // System Constants
  static const String deepLinkScheme = 'sss';
  static const String deepLinkHost = 'qr';
  static const String systemId = 'SSS_SYSTEM_v1';
  static const String version = '1.0.0';

  // Data Fields
  final String id;                    // Unique identifier
  final String data;                  // User-provided content
  final String timestamp;             // ISO 8601 creation timestamp
  final String? customIdentifier;     // Optional letter/emoji
  final String? category;             // Optional title/category
}
```

### JSON Format

```json
{
  "id": "1234567890-abc123",
  "systemId": "SSS_SYSTEM_v1",
  "version": "1.0.0",
  "data": "User content here",
  "timestamp": "2024-01-15T10:30:00.000Z",
  "customIdentifier": "A",
  "category": "My Category"
}
```

### ID Generation
- **Format**: `{timestamp}-{randomHex}`
- **Uniqueness**: Based on microseconds since epoch + hash code
- **Collision Resistance**: Reasonably unique without external dependencies

## Deep Linking System

### Deep Link Flow

```
1. User generates QR code
   ↓
2. System creates QRData with unique ID
   ↓
3. Deep link generated: sss://qr/<id>
   ↓
4. Deep link encoded in QR code
   ↓
5. QR code scanned by device camera
   ↓
6. Device recognizes deep link
   ↓
7. App opens automatically (if installed)
   ↓
8. App navigates to QRDetailScreen with ID
   ↓
9. QR data retrieved from registry and displayed
```

### Deep Link Registration

#### Android
- **Intent Filter**: Configured in `AndroidManifest.xml`
- **Scheme**: `sss`
- **Host**: `qr`

#### iOS
- **URL Scheme**: Configured in `Info.plist`
- **Scheme**: `sss`
- **Host**: `qr`

### Deep Link Parsing
- **URI Parsing**: Uses Dart `Uri` class for parsing
- **Validation**: Checks scheme and host match expected values
- **ID Extraction**: Extracts ID from path segments
- **Error Handling**: Returns null for invalid deep links

## QR Code Generation

### Generation Process

1. **Data Input**: User enters data, title, and optional identifier
2. **QRData Creation**: System creates `QRData` object with:
   - Unique ID generation
   - Current timestamp
   - User-provided data
   - Optional metadata (identifier, category)
3. **Deep Link Generation**: Creates `sss://qr/<id>` URL
4. **Registry Storage**: Stores QRData in in-memory registry
5. **QR Widget Creation**: Generates QR code widget with deep link
6. **Visual Customization**: Applies colors, borders, embedded identifier

### QR Widget Stack

```
Stack
├── QrImageView (base QR code)
│   ├── Data: sss://qr/<id>
│   ├── Size: 200px (configurable)
│   ├── Colors: Custom foreground/background
│   └── Error Correction: Medium (M)
└── Container (embedded identifier overlay)
    ├── Circular background
    └── Text (letter/emoji)
```

### Embedded Identifier
- **Position**: Center of QR code
- **Size**: 20% of QR code size
- **Background**: Circular white background
- **Font Size**: 
  - Emojis: 15% of QR size
  - Letters: 12% of QR size
- **Color**: Matches foreground color (configurable)

## Export and Sharing

### PNG Export

#### Process
1. **Widget Capture**: Uses `RepaintBoundary` with `GlobalKey`
2. **Image Rendering**: Converts widget to `ui.Image` at 3.0x pixel ratio
3. **Byte Conversion**: Converts image to PNG bytes
4. **Permission Check**: Requests storage permission (Android)
5. **File Save**: Writes to downloads directory
6. **User Feedback**: Shows success message with file name

#### Technical Details
- **Pixel Ratio**: 3.0x for high-resolution output
- **Format**: PNG (lossless)
- **File Size**: Varies based on QR size and complexity

### PDF Export

#### Process
1. **Widget Capture**: Same as PNG export
2. **PDF Creation**: Uses `pdf` package to create document
3. **Page Layout**: A4 format with 40px margins
4. **Content Addition**:
   - Title (if provided)
   - QR code image (centered)
   - Description text
   - Timestamp
   - System identifier
5. **File Save**: Writes PDF bytes to downloads directory

#### PDF Structure
```
Page (A4)
├── Title (24pt, bold) - if provided
├── Spacing (20px)
├── QR Code Image (200x200px, centered)
├── Spacing (20px)
```

## System Verification

### Verification Methods

#### 1. Deep Link Verification
```dart
QRData.isSystemDeepLink(scannedData)
```
- Checks if data starts with `sss://qr/`
- Validates URI structure
- Extracts and validates ID format

#### 2. JSON Payload Verification
```dart
QRData.verifySystemQR(jsonString)
```
- Parses JSON string
- Checks for `systemId: "SSS_SYSTEM_v1"`
- Handles parsing errors gracefully

### Verification Flow

```
Scanned Data
    ↓
Is it a deep link? (sss://qr/<id>)
    ├─ Yes → Verified ✓
    └─ No → Is it JSON?
            ├─ Yes → Check systemId
            │   ├─ Matches → Verified ✓
            │   └─ No match → Not verified ⚠
            └─ No → Not verified ⚠
```

### Verification Display

#### Verified QR
- **Color**: Green background (`Colors.green[100]`)
- **Border**: Green border
- **Icon**: Verified checkmark icon
- **Text**: "✓ Verified - Created by SSS System"

#### Unverified QR
- **Color**: Orange background (`Colors.orange[100]`)
- **Border**: Orange border
- **Icon**: Info outline icon
- **Text**: "⚠ Not created by this system"

- **Downloads Folder**: Direct access to Downloads directory
- **Camera**: Full camera access via `mobile_scanner`

### Limitations
- **Web**: No camera access, no file system access
